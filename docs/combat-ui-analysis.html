二、问题清单（按严重程度排列）

  • 严重 空间浪费：四层纵向分割挤压手牌区
    当前布局从上到下分为 Header → TopBar → Stage → Hand → CTA 共 5 个纵向区块。 Header(46px) + TopBar(约 60px) + Stage(弹性) + Hand(约 160px) + CTA(约 80px) = 固定区域已占 ~346px， 实际留给 Stage 战斗舞台的空间仅 ~280px（720-440）。
    影响：多敌人时面板重叠，玩家面板与手牌区视觉竞争。 结束回合按钮独占一行 (220×64)，在 720px 高度下浪费约 11% 的垂直空间。
  • 严重 信息冗余：玩家生命重复显示在 Header 和 Stage 两个位置
    RunHeaderView 的左侧 chip 显示 生命 100/100，同时 stage_root 底部 player_panel 又显示一遍完整的生命条/HP。
    影响：玩家扫描屏幕时需要决定"该看哪个数值"，增加认知负担。StS 只在一处显示玩家 HP（左上资源区）， 战斗舞台只放敌人。
  • 中等 玩家面板位置不合理：居中底部与手牌区竞争空间
    当前玩家面板 (200×280) 在 stage_root 中 水平居中、底部对齐，直接压在即将出现的手牌区上方。
    品类惯例：StS 将玩家放在 左下区域（或简化为状态图标），把舞台中央留给敌人和特效。 玩家不需要巨大的立绘面板——玩家是"自己"，敌人的意图/姿态才是决策焦点。
  • 中等 资源分散：能量球与回合数脱离主资源条
    能量球 (58×58) 和回合数胶囊 (100×44) 放在独立的 top_bar，与 Header 的 HP/卢恩/瓶位物理分离。
    品类惯例：StS 将所有核心资源（HP、护甲、能量、回合、牌堆数、弃牌数）放在同一行。 玩家扫一眼即可获取完整决策信息。当前布局需要目光上下移动两次才能拼出资源状态。
  • 中等 玩家面板过大 (200×280)，挤占舞台空间
    玩家面板尺寸是敌人面板 (150-180 × 210-240) 的约 1.5 倍，且带有大幅立绘区、状态徽章行、血条。
    问题根源：玩家面板复用了与敌人相同的 battle_entity_panel 构建器，但玩家不需要意图横幅、 不需要姿态条、不需要大量状态展示（玩家状态可压缩为图标行贴在左侧）。
  • 轻微 圣杯瓶按钮与手牌徽标混杂在 hand_band 中
    圣杯瓶按钮 (132×54) 与抽牌/弃牌/消耗堆徽标 (52×44) 放在同一个 HBoxContainer， 视觉层级与手牌卡片混淆。圣杯瓶是 CTA 按钮而非信息徽标，应该与"结束回合"同属底部操作栏。
  • 轻微 日志折叠按钮过于隐蔽，与战斗舞台割裂
    日志默认折叠后只剩 24px 宽的窄条，在 mid_area 左侧。虽然"默认折叠"是正确的（交战区优先）， 但折叠后与舞台之间没有明确的视觉分隔，容易误触。

三、建议改进方案

🔧 方案 A：StS 式单行资源条（推荐，改动最小）

目标：消除 TopBar 和独立 CTA 行，释放 ~140px 垂直空间给战斗舞台。

具体改动：
1. 将 Header 改为战斗资源单行：[❤️ HP] [🛡️ 护甲] [⚡ 能量球] [回合] [📥 抽牌] [📤 弃牌]
2. 将"结束回合"和"圣杯瓶"放入底部操作栏（hand_band 下方的一行，高度 ~50px）
3. 移除 TopBar 和 CTA_band，Stage 区向下延伸
4. 玩家面板简化为左侧紧凑状态列 (120px 宽)，去掉立绘区，只保留 HP 条 + 状态图标

🔧 方案 B：玩家左侧化（解决面板竞争）

目标：玩家不在舞台中央底部，避免与手牌区重叠。

具体改动：
1. Stage 改为 HBox：左侧玩家紧凑面板 (120px) + 右侧敌人舞台 (弹性展开)
2. 敌人保持水平排列居中
3. 玩家面板高度缩减至 160px，仅显示立绘 + HP 条 + 状态图标行
4. 掉落区从"舞台中间"改为"敌人面板本身"（已实现 DropZone）

🔧 方案 C：信息优先级重排

目标：消除重复信息，每类数据只出现一次。

优先级表：
• HP / 护甲 → 资源单行左侧（不放在 Stage 玩家面板）
• 能量 / 回合 → 资源单行居中
• 牌堆数 → 资源单行右侧
• 卢恩 / 瓶位 → 全局 Header 左侧（非战斗数据）
• 大卢恩 / 癫火 → 全局 Header 右侧（仪式状态）
• 敌人意图 → 敌人面板上方（已有，保持不变）
• 玩家状态（腐败/出血等）→ 紧凑贴在资源条 HP 下方，不独立成面板
