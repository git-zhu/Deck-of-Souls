# 战斗 UI 重构（游戏化与信息层级）— 设计规格 + 实施记录

> 日期：2026-05-23
> 目标：以游戏化和信息层级为目标重构战斗 UI；**不改变战斗/卡牌/状态逻辑，仅重构展示层**。

---

## 1. 问题清单 → 方案对照

| # | 原问题 | 方案 | 状态 |
|---|--------|------|------|
| 1 | 玩家/敌人面板过大、空白多 | 紧凑 HUD（`compact_fighter_hud`，228px 宽，名字+大号HP+细血条+状态chip） | ✅ |
| 2 | 中央战斗区域无视觉主体 | `combat_stage`：镀金框内 玩家圆章 ⚔ 敌人圆章 | ✅ |
| 3 | 顶部信息混杂 | 顶行只放 玩家HUD 左 / 敌人HUD 右，互不干扰 | ✅ |
| 4 | 敌人意图强调不足 | `intent_banner`：高亮面板 + 语义色描边 + 大字号 + 图标 + 攻击意图脉冲 | ✅ |
| 5 | 手牌像大按钮 | 游戏化卡牌：语义色描边/阴影 + 消耗徽章 + 卡名/类型/效果文本层级 | ✅ |
| 6 | 卡内文本层级不明 | 卡名 15px 亮色 > 类型 11px 语义色 > 效果 12px（数值金色高亮） | ✅ |
| 7 | 颜色随机 | `GameTheme.card_type_color`：武器金/盾牌青/战灰紫/魔法红/祷告绿/瓶绿/壶橙/传说深红 | ✅ |
| 8 | 资源纯文字 | `resource_chip`：抽牌/弃牌/消耗/集中 紧凑 chip（图标+数值） | ✅ |
| 9 | 结束回合权重不足 | `end_turn_button`：金色主 CTA、右下固定、hover/pressed/disabled、快捷键 [E] | ✅ |
| 10 | 圣杯瓶普通文本 | `flask_button`：独立绿色治疗按钮 + 快捷键提示 | ✅ |
| 11 | 战斗日志抢注意力 | 底部 44px 细条、13px 弱化字体、低透明度 | ✅ |
| 12 | Debug 数据暴露 | `get_window().title` 覆盖调试后缀；HUD 只展示计算值 | ✅ |
| 13 | 分辨率适配 | 1280×720 校验（`ui_screen_test` / `smoke_test` 通过） | ✅ |

## 4. 验证

- `combat_hud_test`：HUD 结构、意图标签、日志非空。
- `smoke_test`：6 出身跑通战斗，敌人面板不越界，手牌行 ≤210px。
- `ui_screen_test`：9 屏 1280×720 边界校验。
- `input_test`：快捷键（数字/F/空格/D/Esc）验证。
- 全量 28 项 headless 测试通过。

---

## 5. 非目标

- 不改战斗逻辑/卡牌效果/状态计算（本次零逻辑改动）。
- 不引入外部美术（沿用自产 SVG 背景）。
- 卡牌数值展示仍来自 `CardData.text`（数值高亮为展示层处理）。
